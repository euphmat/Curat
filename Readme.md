# Curat

YouTube のゲーム実況プレイリストを、動画ごとの視聴進捗とともに管理する静的 Web アプリです。
ビルド工程やサーバーは不要で、そのまま GitHub Pages に配置できます。

## 主な機能

- プレイリスト URL からタイトル、サムネイル、全動画を取得
- 実況者のプレイリストが降順でも、動画タイトルを解析して Part 1 から自動整列
- 同じゲームの複数プレイリストを、フォルダーとして階層管理
- VS Code 風のエクスプローラーで、空フォルダー作成、検索、展開・折りたたみ、横幅変更に対応
- 英字のフォルダー名を読みやすい UpperCamelCase で表示し、Iconify 検索または内蔵カラー SVG からフォルダーアイコンを設定可能
- フォルダー／プレイリストの右クリック・長押しメニュー、ツリーに追従するフォルダー編集ポップアップ、入力中の名前候補、縦スクロール対応のアイコン一覧、削除確認ダイアログ
- RPG向けフォルダーアイコンに [Game Icons](https://game-icons.net/)（CC BY 3.0）を使用
- プレイリストをマウスのドラッグまたは指のスライドで任意に並び替え、フォルダー間の移動とツリー上の視聴進捗確認に対応
- ゲームの正式名と別名を登録し、完全一致・fzf 風の部分列評価・編集距離で表記ゆれを吸収
- 自動分類したプレイリスト名を学習用の別名DBへ追加し、次回以降の分類精度を改善
- デスクトップ、モバイルともにサイドバーを開閉可能
- 左のエクスプローラーで選んだプレイリストの詳細とエピソードを、中央ワークスペースに表示
- ヘッダーから YouTube プレイリスト URL をすぐに追加
- プレイリスト内の動画をドラッグ＆ドロップして任意に並び替え、再同期後も手動順を維持
- 登録済みプレイリストの作品名と投稿者から YouTube 全体を検索し、「新しい投稿者」「追加済みの投稿者」「新しいゲーム」「新しいゲーム AND 新しい投稿者」ごとに、更新のたび前回と異なる候補を8件表示。不要なプレイリスト、ゲーム、チャンネルは以後の候補から除外可能
- 動画ごとに「未視聴」「視聴中」「視聴済み」「スキップ」を管理
- 1 プレイリストにつき「視聴中」は 1 本だけ
- ヘッダーから登録中の全プレイリストとフォルダーを一括削除
- 再同期時は既存の進捗を維持し、新着動画だけを追加
- Firebase への自動保存、JSON のエクスポート／インポート、端末間リアルタイム同期
- オフライン用のアプリシェルキャッシュ
- PC・タブレット・スマートフォン対応（iPad の縦向き・横向き、ホーム画面追加、Safe Area 対応）

## ローカルで確認

ES Modules と Service Worker を使うため、ファイルを直接開かずローカルサーバーを起動します。

```sh
python3 -m http.server 4173
```

ブラウザで `http://localhost:4173` を開いてください。

## iPad での操作

- タップ: フォルダーを展開し、プレイリストや各操作を選択
- 長押し: フォルダー／プレイリストの操作メニューを表示
- スライド: プレイリストまたはエピソード横のグリップを上下へ動かして並べ替え
- ホーム画面へ追加: Safari の共有メニューから「ホーム画面に追加」を選択

iPad では縦向き・横向きのどちらでもエクスプローラーとワークスペースを2ペインで表示します。
画面端の Safe Area、指で押しやすい操作領域、スクロール中の誤操作防止にも対応しています。

## YouTube API の準備

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成
2. YouTube Data API v3 を有効化
3. API キーを作成
4. 本番用キーには「ウェブサイトの制限」を設定し、GitHub Pages の URL を許可
5. Curat の「設定と保存データ」から API キーを入力して保存

API キーは使用中のブラウザに保存され、ページを再読み込みしても復元されます。
JSON エクスポートには含めません。
公開リポジトリのソースへ API キーを書き込まないでください。

「おすすめ」はボタンを開いたとき、または「候補を更新」を押したときだけ検索します。
各タブは候補が十分にある場合、直前に表示したプレイリストを避けて8件ずつ入れ替えます。
1 回の更新で、登録数にかかわらず YouTube のプレイリスト検索は最大 8 回です。

## データ保存のルール

進捗は使用中のブラウザ（IndexedDB）へ保存し、ログイン中は Firebase Realtime Database
にも自動保存します。同じアカウントでログインした iPad・パソコン間にはリアルタイム反映
されます。

プレイリストや進捗データは再読み込みや一時的なオフライン状態でも端末から復元されます。
API キー、Firebase のユーザー名とパスワード、ログイン状態も使用中のブラウザに保存されます。
ブラウザのサイトデータを消去した場合は端末内データも削除されるため、Firebase 同期または
JSON バックアップを併用してください。

JSON の手動エクスポート／インポートは引き続き利用できます。API キーとログイン情報は JSON
に含まれません。

## 0 円の端末間同期を設定

同期には Firebase Authentication と Realtime Database の Spark（無料）プランを使います。
Spark プランは支払い方法の登録が不要で、Realtime Database は 1 GB 保存・月 10 GB
ダウンロードまで無料です。個人用の Curat では十分な容量です。上限を超えた場合も Spark
プランのままなら課金されず、その月のサービスが停止します。

### 1. Firebase プロジェクトを作成

1. [Firebase Console](https://console.firebase.google.com/) でプロジェクトを作成
2. Google Analytics は Curat には不要なので無効で構いません
3. 「プロジェクトの設定」→「マイアプリ」→ Web（`</>`）を選び、Web アプリを登録
4. 表示された `firebaseConfig` を控える

### 2. メール／パスワード認証を設定

1. Firebase Console の「Authentication」→「始める」
2. 「Sign-in method」で「メール／パスワード」を有効化
3. 「Users」→「ユーザーを追加」で、自分用のメールアドレスと十分に強いパスワードを登録
4. 作成されたユーザーの「ユーザー UID」を控える
5. 「Settings」→「Authorized domains」に GitHub Pages のホスト名
   （例: `USERNAME.github.io`）がなければ追加

アプリから新規ユーザーを作る機能は意図的に用意していません。Firebase Console で作った
1 アカウントだけを使います。

### 3. Realtime Database とセキュリティルールを設定

1. Firebase Console の「Realtime Database」→「データベースを作成」
2. 場所は近いリージョンを選択
3. セキュリティルールはロックモードで開始
4. [firebase-database-rules.json](./firebase-database-rules.json) の
   `ここを自分のFirebase_UIDへ置換`（3 箇所）を手順 2 の UID に置き換える
5. Realtime Database の「ルール」へ内容を貼り付け、「公開」

このルールにより、その UID でログインした本人だけが Curat データを読み書きできます。

### 4. Curat に Firebase の接続情報を設定

[firebase-config.js](./firebase-config.js) を開き、手順 1 の `firebaseConfig` の各値を貼り付けます。
Realtime Database 作成後の設定に含まれる `databaseURL` も必須です。

```js
export const firebaseConfig = {
  apiKey: "AIza...",
  authDomain: "PROJECT_ID.firebaseapp.com",
  databaseURL: "https://DATABASE_NAME.REGION.firebasedatabase.app",
  projectId: "PROJECT_ID",
  appId: "1:...",
};
```

Firebase の Web 用設定値は公開前提の識別情報であり、秘密鍵ではありません。データ保護は
手順 3 のセキュリティルールで行います。設定済みファイルを GitHub へ commit / push し、
GitHub Pages の更新を待ってください。

### 5. 各端末でログイン

1. 更新後の Curat を開く（古い表示なら再読み込み）
2. 左下の「保存データ」を開く
3. 手順 2 で作った同じメールアドレスとパスワードでログイン
4. 表示が「すべての端末で同期中」になったことを確認
5. iPad とパソコンの両方で同じ操作を行う

ログイン情報とログイン状態は使用中のブラウザに保存されるため、通常は再読み込み後も維持されます。
共用端末では利用後にログアウトし、必要に応じてブラウザのサイトデータも削除してください。
Firebase に既存データがあればログイン直後に読み込まれます。同期後も念のため、ときどき
「バックアップを保存」で JSON を手元に残すことを推奨します。

## タスク管理ルール

1. 1 件の実況プレイリストを 1 つの視聴管理単位として扱う
2. 初回はプレイリスト名をゲームタイトルのフォルダー名にし、正式名と別名をあとから編集できる
3. 新しいプレイリスト名を、正式名・手動登録した別名・過去に学習した表記ゆれと照合する
4. 作品番号（例: `FINAL FANTASY` と `FINAL FANTASY Ⅱ`）の違いは別作品として扱い、それ以外は完全包含を最優先に、fzf 風の部分列評価と編集距離による近似値を使って、十分な確度と候補間の差があるフォルダーへ自動分類する
5. 自動分類したプレイリスト名は学習用の別名DBへ保存し、追加直後に手動で別フォルダーへ移動した場合は移動先の編集可能な別名へ昇格して、次回以降の照合にも利用する
6. 十分な確度がない、または候補が拮抗するタイトルだけを新しいフォルダーにする
7. 公開中の各動画を、プレイリスト順に 1 タスクとして作成
8. 動画タイトルから `Part 1`、`Pt.1`、`EP1`、`#1`、`パート1`、`第1話`、`その一`、`S1E2` などを検出する
9. 全角数字・漢数字・英語数字・ローマ数字を数値へ変換し、シーズン、話数、前編／中編／後編の順に整列する
10. プロローグ・序章は先頭、最終回・完結編は末尾に配置する
11. 話数を判定できない動画は、判定済み動画の後ろで YouTube 上の相対順序を維持する
12. 初回取り込み時の状態は「未視聴」
13. 動画を開くと「視聴中」になり、同じプレイリストで以前「視聴中」だった動画は「未視聴」に戻る
14. チェックを入れると「視聴済み」
15. 状態ボタンは「未視聴 → 視聴中 → 視聴済み → スキップ」の順で切り替わる
16. 再同期で追加された動画は「未視聴」、YouTube 側から消えた動画は履歴保持のため非表示アーカイブ
17. 視聴進捗率は「視聴済み ÷（スキップを除く有効動画）」で計算

## GitHub Pages で公開

このフォルダーを GitHub リポジトリのルートへ push し、リポジトリの
`Settings → Pages → Build and deployment` で `Deploy from a branch` を選びます。
対象ブランチと `/ (root)` を指定すると公開できます。

すべてのアセット参照は相対パスなので、`https://USER.github.io/REPOSITORY/` 形式でも動作します。
